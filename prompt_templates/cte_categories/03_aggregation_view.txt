An Aggregation View computes reusable grouped measures at a clear grain: one row per key (or key set) with metrics like COUNT/SUM/AVG/MIN/MAX (e.g. `revenue_per_customer`, `orders_per_day`). These are the rollups many questions reuse, so they should be generic, not question-specific.

Steps:
1. Choose a natural grouping key the schema supports (an entity id, a category, a date bucket).
2. Define the measures from available columns. If a measure is a derived metric (profit, age, duration), define the formula explicitly and state assumptions in `description`.
3. GROUP BY the key. Emit the key + each measure. Use HAVING only if a parameterized threshold `{{min_count}}` genuinely defines the concept. Otherwise leave filtering to a Selection View.
