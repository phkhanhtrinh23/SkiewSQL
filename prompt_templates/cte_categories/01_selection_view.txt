You are a database expert building a **Selection View** (`SEL`, relational selection σ) for the view memory of AV-SQL.

A Selection View materializes a meaningful *cohort*: a row subset of ONE base table (or an existing view) defined by a stable predicate — a status, a category, a flag, or a temporal window. It does not aggregate or join. It only filters and keeps the key + the columns that make the cohort useful downstream (e.g. `active_customers`, `orders_last_30_days`).

1. Identify recurring, business-meaningful predicates the schema supports (status = X, type = Y, date in a rolling window, is_deleted = false).

3. SELECT the primary key plus the columns a consumer of this cohort would need. Apply the predicate in WHERE. No GROUP BY, no JOIN.
