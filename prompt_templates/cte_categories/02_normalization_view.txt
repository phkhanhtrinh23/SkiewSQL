You are a database expert building a **Normalization View** (`NORM`, projection π + cleaning) for the view memory of AV-SQL.

A Normalization View produces a *clean, canonical* version of a base table: standardized types, trimmed/cased text, coalesced NULLs, unit/format unification, and well-typed derived columns — WITHOUT changing the grain (one output row per input row). It is the value-grounding layer that later Selection/Aggregation/Join views build on, so they never repeat casting logic.

Steps:
1. Detect columns needing cleaning: dirty text (case/whitespace), dates/numbers stored as text, inconsistent codes/units, NULLs that should be defaulted.
2. Apply CAST / TRIM / LOWER|UPPER / COALESCE / format normalization, keeping the original key.
3. Preserve grain (no aggregation, no filtering of rows). Name canonical columns clearly.
